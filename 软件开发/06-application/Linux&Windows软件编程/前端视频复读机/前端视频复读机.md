

# 需求描述


应用名称视频复读机
我想开发一款视频编辑器，用来在视频的基础上做草稿，比如视频播放到某个时间的某个画面，我暂停把草稿画上，后续播放到此处会有草稿显示。
我想在上面基础上，增加视频时间点标记和播放时长标记，比如我在00:12:36 即12分36秒的位置标记为一个标记点A_begin，从该标记点播放至A_end，也就是说每个标记点对象至少有开始时刻 (hh:mm:ss) 和结束时刻，视频时长范围内还有其他类似的标记点BCDEF...，后续可以只跳转播放选中的标记点序列，然后可以反复播放这几个标记点对应的视频片段(片段里如果有草稿，也要正常显示草稿)。并未标记点序列组成的视频片段可以带着草稿导出。我实现这功能的目的是做一个用于学英语的视频编辑器，原视频是英文原音的视频（底部配有中英字幕，不是独立字幕文件是硬编码到视频里的），观看到不理解或者生疏的位置可以随时暂停做标记和笔记。

另外关于对视频帧做草稿(canvas)，每个草稿对象(笔画、文字标签等)持续多少帧，这个我没经验怎么实现，但是我只知道怎么用，比如这个视频片段里，这句字母里有我不认识的单词，我给这句字幕打上草稿，草稿持续时间(即该草稿对象的显示的声明周期最长不超过字幕消失时刻，但是原视频的字幕是硬编码到视频里的，所以无法通过字幕文件获取时长，不光是字幕草稿，任何画面草稿持续多长时间，这个实现从技术上我暂时没经验，我只知道具体的某个画面的草稿要显示多长时间，就像现在的常规视频编辑一样，一个特效持续时长可以在下方各自的编辑轨道上拉长到合适的时刻位置。



# 核心需求梳理


针对**硬字幕英文原片**做英语复读学习：视频帧手绘草稿、时间片段标记、片段序列循环复读、带草稿完整导出，生词 / 句子可标注固定时长显示。



**三大核心模块**

1. **Canvas 帧草稿系统**：手绘笔画、文字标签，每条草稿独立生命周期（起止时间，时间轴轨道拖拽拉长缩短）
2. **片段标记复读系统**：标记点 (片段 A_begin/A_end)、多片段序列管理、选中序列连续 / 循环播放
3. **合成导出系统**：原视频 + 全部草稿图层叠加，导出完整 MP4 学习素材；
4. 片段序列导出：导出选中的片段序列（比如ACE等自由组合的序列）+ 各个片段内的草稿图层叠加


---

整体分层架构 Tauri（Rust 后端 + Vue3/React 前端）

```txt
UI层：预览播放器 + 时间轴轨道面板 + 标记列表 + 绘图工具栏
├─ 播放控制层：video原生播放器 + 时间时钟同步器
├─ 时间数据管理层（核心）

└─ 导出合成层：Rust 侧直接调用 FFmpeg 二进制 / 静态链接 帧合成编码导出
```

时间工具统一标准
视频 FPS 默认 30，帧时间 = 1/30 s。或者从 .mp4 文件中解析获取视频的帧率。

草稿对象 DraftItem（解决草稿生命周期问题）
每条草稿独立拥有**生效起止时间**，对应时间轴轨道上可拖拽拉伸的块，和剪映文字 / 贴纸轨道逻辑完全一致.
解决你疑问：草稿持续时长不靠帧计数，靠**绝对视频时间戳**；用户画完草稿后，下方草稿轨道会生成一个色块，左右拖拽直接修改`startTime/endTime`，匹配硬字幕出现 / 消失区间。

```js
// string-time.js
/**
 * 时间字符串 "hh:mm:ss.fff" 转 总秒数
 * @param {string} timeStr
 * @returns {number}
 */
function timeStrToSec(timeStr) {
    // 空字符串直接返回0，不报错
    if (!timeStr || timeStr.trim() === "") {
        return 0;
    }

    const [h, m, s] = timeStr.split(':');
    const [sec, ms = '000'] = s.split('.');
    return Number(h)*3600 + Number(m)*60 + Number(sec) + Number(ms)/1000;
}

/**
 * 总秒数 格式化输出 "hh:mm:ss.fff"
 * @param {number} secNum
 * @returns {string}
 */
function secToTimeStr(secNum) {
    const h = Math.floor(secNum / 3600);
    const rem = secNum % 3600;
    const m = Math.floor(rem / 60);
    const s = Math.floor(rem % 60);
    const ms = Math.round((secNum - Math.floor(secNum)) * 1000);
    const pad = n => String(n).padStart(2, '0');
    const padMs = n => String(n).padStart(3, '0');
    return `${pad(h)}:${pad(m)}:${pad(s)}.${padMs(ms)}`;
}

// 我们自己实现的模块，手动挂载到window全局，所有script都能调用
if (typeof window !== 'undefined') {
    window.timeStrToSec = timeStrToSec;
    window.secToTimeStr = secToTimeStr;
}
```

### JS-DOM传递


方案 1：主模块提前 getElementById，传 DOM 对象（推荐）
**性能方面**：仅在主模块初始化执行**1 次 DOM 查询**，后续所有子模块直接复用引用；子模块内部无任何 DOM 查找操作，事件绑定、属性读取零查询损耗。
**内存方面**：只是传递对象引用（浅拷贝，不复制 DOM 节点），内存开销几乎为 0；仅存一份 DOM 引用，多处共用不会重复创建节点缓存。

```js
// 主模块
const btn = document.getElementById("batchTextSizeBtn");
initTextTool(btn);
```

下面用简单的代码来演示。


```js
/**
 * @param {HTMLElement} videoEl 视频DOM
 * @param {Function} log 注入的日志函数
 */
function createVideoTool(videoEl, log) {
    const DOMvideoEl = videoEl;

    function video_pause()
    {
        if(!DOMvideoEl.paused) {
            DOMvideoEl.pause();
            log('📌 视频已暂停定格');
        }
    }

    function video_play()
    {
        if(DOMvideoEl.paused) {
            DOMvideoEl.play();
            log('📌 视频已开始播放');
        }
    }

    // 对外函数
    return {
        // 左边表示对外属性名:右边表示本模块函数名
        video_pause: video_pause,
        video_play
    };
}

// 或者挂载到全局（传统方式）
if (typeof window !== 'undefined') {
    window.createVideoTool = createVideoTool;
}
```

### JS-多依赖注入


如果模块依赖很多东西，用对象打包（推荐统一规范）

```js
function createVideoTool(videoEl, deps) {
    // 统一取出所有依赖
    const { log, timeTools } = deps;

    function video_pause() {
        videoEl.pause();
        const nowSec = timeTools.timeStrToSec("00:01:00");
        log(`视频暂停，当前时间秒数：${nowSec}`);
    }
    return { video_pause };
}
```

主页面调用：
```js
const logTool = createLogTool(logBox);
```

外部注入 和 函数参数 的区别

```js
const videoTool = createVideoTool();
videoTool.video_pause(videoDom); // 把dom当作参数,每次调用都传一遍

// 不想每次调用其内部接口都传递这个dom, 则在创建时就传给它
const videoTool = createVideoTool(videoEl);
```


---

普通传参：只是临时给本次调用提供数据；
依赖注入：主动把「长期依赖」从内部硬编码剥离，统一由外部供给。
标准应用：实时变化的输入信息就作为参数传递，那种恒定不变的就推荐作为依赖注入。



### JS-普通和异步函数


async function 和 function
普通函数，代码从上到下**一行执行完，才走下一行**，中间遇到耗时操作会卡住后面代码。
异步函数，函数内部遇到 await 会**暂停当前函数内部代码**，但不会阻塞页面其他 JS；无论你内部 return 什么，最终返回值一定是 `Promise` 对象。


```js
function getHtmlCode() {
	await loadHtml("./log-panel.html");
	log("页面初始化完成");
}
```

await 用人话讲，就是在异步函数内部，阻塞等待网络请求 / 延时等异步操作完成，再执行下一行代码，不用嵌套一堆回调。虽然函数内部阻塞，但不会阻塞外部的代码执行。哪怕内部有等待网络的操作，页面其他按钮、打印日志照常响应，不会卡死。

```js
        <p>丢失：${failNumber} / ${maxFailNumber}</p>
    `;
}

/**
 * 创建一个随机字母，生成可移动的元素，然后将其添加到数组中
 */
function startProduce() {
    clearInterval(produceTimer);
    produceTimer = setInterval(() => {
        new Letter();
    }, 1000);
}

function getRandomLetter() {
    var code = getRandom(65, 65 + 26);
    return String.fromCharCode(code);
}

function getRandom(min, max) {
    return Math.floor(Math.random() * (max - min) + min);
}

function startMove() {
    clearInterval(moveTimer);
    moveTimer = setInterval(() => {
        for (var i = 0; i < letters.length; i++) {
            var item = letters[i];
            item.move(16);
            if (item.outOfRange()) {
                item.kill();
                i--;
                failNumber++;
                showScore();
                if (failNumber === maxFailNumber) {
                    gameOver();
                }
            }
        }
    }, 16)
}

function gameOver() {
    stop();
    gameOverDom.style.display = "block";
    window.onkeydown = null;
}

function start() {
    startProduce();
    startMove();
}

function stop() {
    clearInterval(moveTimer);
    clearInterval(produceTimer);
}

start();
showScore();

window.onkeydown = function (e) {
    if (e.key.length === 1) {
        var k = e.key.toUpperCase();
        var letter = letters.find(it => it.letter === k);
        if (letter) {
            letter.kill();
            score += 10;
            showScore();
        }
    }
}
```

# excalidraw画布不失真

excalidraw 里有用到画布(canvas)技术吗？为什么在它上面绘制的笔记，基本上能无限放大也不失真模糊？

数据存储 / 导出 / 无限缩放底层：SVG 矢量数据
所有你画的图形不会直接存 Canvas 像素，而是完整保存**矢量几何数据**，这是放大不模糊的关键。
Canvas 是**光栅位图**，单纯放大画布会糊；
Excalidraw 只是用 Canvas 做**临时实时预览**，真正图形数据是矢量，缩放时重新在 Canvas 重绘，不是拉伸像素。

---

Excalidraw 内部会把每一笔拆解成标准化矢量对象，存入 JSON：
- 直线：起点 (x,y)、终点 (x,y)、粗细、颜色；
- 手绘涂鸦：一串贝塞尔曲线点集合 `[x1,y1,cp1x,cp1y,x2,y2...]`
- 矩形 / 圆形 / 文字：坐标、宽高、圆角、字体参数
- 箭头、连接线：同样是几何坐标，无像素信息。

它不保存画布上的像素色块，只存数学坐标曲线，和分辨率无关。


---

Excalidraw 缩放逻辑：

滚轮缩放 / 拖拽放大时，记录当前视口缩放系数 `scale`、偏移 `offsetX/offsetY`；
清空整个 Canvas；
根据缩放系数，用原始矢量坐标重新计算所有图形在当前视口的位置；
用 Canvas 2D 重新绘制一遍所有曲线、线条；
线条粗细、文字大小会跟着 scale 同步换算，线条不会变粗糊，曲线永远平滑。

等于每次放大都是**重新画一张高清图**，不是把小图拉大。


---

excalidraw对图片的保存，也会比普通图片查看器/编辑器清晰，也就是说，把粘贴到excalidraw画板中的图片，放大，也会变得清晰。

excalidraw 放大图片清晰是两套存储 + 渲染机制共同实现的

普通工具逻辑：
- 图片加载后，直接渲染到固定像素画布；
- 缩放时只是**拉伸已经渲染好的像素点阵**；
- 原始图片像素固定，放大后像素被拉大，出现马赛克、模糊。


Excalidraw 插入图片放大清晰的完整底层原理
（1）分离存储：原图二进制单独永久保存，不丢原始像素

Excalidraw 采用**二元分离存储架构**：
1、只存图片的**矢量定位信息**：`image` 元素的 x/y 坐标、宽高、旋转、裁切、透明度，**不存图片像素**。
2、粘贴 / 上传图片时，**完整保存原始图片二进制数据流**（原图完整分辨率，100% 无损，不会压缩降级）。

（2）缩放逻辑：从不拉伸旧画面，每次缩放完整重绘原图
- 记录视口缩放系数`scale`、画布偏移；
- 清空整个渲染 Canvas；
- 取出**原始高清图片二进制**，重新创建完整尺寸`Image`对象；
- 根据当前视口 scale，用 Canvas API `drawImage` 重新绘制图片；
- 开启浏览器高质量图像平滑：`ctx.imageSmoothingQuality = "high"`，插值算法优化放大过渡；
- 几何图形（线条 / 矩形 / 文字）按矢量坐标同步重绘。

核心区别：**每次放大都拿原始高清原图重新渲染，不是拉伸小图**。

（3）Canvas 高 DPI 设备适配（Retina 屏幕更清晰）
Excalidraw 渲染时自动读取 `window.devicePixelRatio`，把 Canvas 内部像素尺寸放大多倍，解决高分屏模糊：
```js
// 伪代码
const dpr = window.devicePixelRatio;
canvas.width = viewWidth * dpr;
canvas.height = viewHeight * dpr;
ctx.scale(dpr, dpr);
```

屏幕 1 个 CSS 像素对应 2/3 个物理像素，图片放大后边缘更细腻，不会发虚。

（4）矢量定位 + 位图分离，缩放只改变坐标，原图无损
